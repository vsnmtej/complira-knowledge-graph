# Proposed Design — cse-situation-explainability

**Version:** 1.0  
**Status:** Draft  

---

## Architecture Decisions

### AD-01: Pull from ArangoDB at request time (no caching)
Explainability fields are computed on every `/v1/situation/ciso` and `/v1/situation/board`
call, exactly like all other fields in those responses. No separate cache — the existing
ArangoDB query pattern is used. When no simulation has run, both fields gracefully return
empty list / None.

### AD-02: Explanations assembled from existing data — no new LLM calls
`threat_category_explanations` is built by joining `threat_category_rollups` → `run_id` →
`attack_chain_findings[].explanation`. The `explanation` JSON was generated by
`report_agent._gen_chain_narratives()` and is already stored. No new LLM inference needed.

### AD-03: Derivation narrative assembled from counterfactuals — no new LLM calls
`exposure_derivation` is assembled from `simulation_runs.counterfactuals[]` (also already
stored). The `narrative` field is constructed in Python from the structured counterfactual
data, not generated by LLM. This is deterministic and fast.

### AD-04: New model fields are optional with empty defaults
`ThreatCategoryExplanation` and `ExposureDerivation` are optional fields on their parent
models. When absent (no simulation run), the API response omits them or returns `null`/`[]`.
Existing consumers are unaffected.

### AD-05: CVE abstraction boundary enforced at AQL layer
Both new AQL queries return only fields from `explanation` (already CVE-free by construction
from the report agent) and `counterfactuals` (also CVE-free). The AQL itself filters out
any `cve_id` references, matching the existing module constraint.

## New Models (`situation/models.py`)

```python
class ThreatCategoryExplanation(BaseModel):
    bucket_name: str
    driving_events: list[str]           # key events that drove breach probability
    turning_point_round: int | None     # round where probability jumped most
    effective_defender_actions: list[str]  # what the defender did that worked
    what_would_have_helped: str         # single_countermeasure from chain narrative

class ExposureDerivation(BaseModel):
    narrative: str                      # plain-English derivation (no CVE IDs)
    contributing_chains: int            # number of chains feeding TEF estimate
    highest_confidence_chain: str       # description of top chain (no CVE IDs)
    investment_recommendation: str      # from counterfactuals[0]
```

**Changes to existing models:**
```python
class CISOSituation(BaseModel):
    ...
    threat_category_explanations: list[ThreatCategoryExplanation] = []  # new

class BoardSituation(BaseModel):
    ...
    exposure_derivation: ExposureDerivation | None = None  # new
```

## New AQL Queries (`queries/situation_abstraction_queries.py`)

### C-05: Chain narratives by tactic bucket

```aql
-- _AQL_CHAIN_NARRATIVES_FOR_BUCKET
FOR r IN threat_category_rollups
  FILTER r.tenant_id == @tenant_id
  FILTER r.bucket_name == @bucket_name
  LIMIT 1
  LET run_id = r.run_id
  FOR f IN attack_chain_findings
    FILTER f.run_id == run_id
    FILTER f.explanation != null
    SORT f.confidence DESC
    LIMIT 3
    RETURN {
      technique_id:          f.explanation.technique_id,
      entry_point_reasoning: f.explanation.entry_point_reasoning,
      success_reasoning:     f.explanation.success_reasoning,
      defender_response:     f.explanation.defender_response,
      soc_blind_spot:        f.explanation.soc_blind_spot_explanation,
      single_countermeasure: f.explanation.single_countermeasure,
      confidence:            f.confidence
    }
```

Note: `f.explanation` is the JSON object written by `report_agent._gen_chain_narratives()`.
No CVE IDs are present in any of these fields by construction.

### C-07: Counterfactuals for latest run

```aql
-- _AQL_COUNTERFACTUALS_FOR_RUN
FOR r IN simulation_runs
  FILTER r.tenant_id == @tenant_id
  FILTER r.status == "completed"
  SORT r.completed_at DESC
  LIMIT 1
  RETURN {
    run_id:          r._key,
    counterfactuals: r.counterfactuals,
    chain_count:     r.chain_count,
    audit_trail:     r.audit_trail
  }
```

## `compute_ciso()` Extension (`abstraction_layer.py`)

After building `threat_categories`, add:

```python
# Build threat category explanations (C-19)
threat_category_explanations = []
for rollup in rollups:
    narratives = get_chain_narratives_for_bucket(
        db, tenant_id, rollup["bucket_name"]
    )
    if not narratives:
        continue
    threat_category_explanations.append(
        _build_category_explanation(rollup, narratives)
    )
```

Helper `_build_category_explanation(rollup, narratives)`:
- `driving_events`: list of `entry_point_reasoning` strings from top-2 narratives
- `turning_point_round`: None (not stored per-bucket; enrichment-ready)
- `effective_defender_actions`: list of `defender_response` strings from narratives
- `what_would_have_helped`: `narratives[0]["single_countermeasure"]`

## `compute_board()` Extension (`abstraction_layer.py`)

After computing `breach_probability_pct`, add:

```python
# Build exposure derivation (C-20)
run_data = get_counterfactuals_for_tenant(db, tenant_id)
exposure_derivation = _build_exposure_derivation(
    run_data, breach_probability_pct,
    financial_exposure_low, financial_exposure_high
) if run_data else None
```

Helper `_build_exposure_derivation(run_data, bp_pct, low, high)`:
```python
counterfactuals = run_data.get("counterfactuals") or []
chain_count     = run_data.get("chain_count") or 0
top_cf          = counterfactuals[0] if counterfactuals else {}

# Narrative assembled in Python — no LLM call
low_m  = (low or 0) / 1_000_000
high_m = (high or 0) / 1_000_000
narrative = (
    f"Exposure of ${low_m:.1f}M–${high_m:.1f}M is derived from "
    f"{chain_count} confirmed attack chain{'s' if chain_count != 1 else ''} "
    f"with {bp_pct:.0f}% breach probability. "
    + (top_cf.get("impact_if_applied", "") or "")
)

return ExposureDerivation(
    narrative=narrative,
    contributing_chains=chain_count,
    highest_confidence_chain=top_cf.get("current_state", ""),
    investment_recommendation=top_cf.get("intervention_description", ""),
)
```

  ...

### `situation/page.tsx` (C-09, C-10)

**CISO:** In `cisoAlerts()`, when building `AlertItem` for each `ThreatCategory`,
if a matching `ThreatCategoryExplanation` exists, append its `what_would_have_helped`
to the `detail_rows`:

```typescript
const explanation = ciso.threat_category_explanations?.find(
  e => e.bucket_name === tc.bucket_name
);
detail_rows: [
  ...existingRows,
  ...(explanation ? [{ key: "What would help", value: explanation.what_would_have_helped }] : []),
]
```

**Board:** In `boardAlerts()`, if `board.exposure_derivation` exists, prepend a
`compliance`-type alert card with `board.exposure_derivation.narrative` as the summary
and `investment_recommendation` as a detail row.
