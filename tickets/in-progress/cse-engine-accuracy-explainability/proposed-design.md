# Proposed Design — cse-engine-accuracy-explainability

**Version:** 1.0  
**Status:** Draft  

---

## Architecture Decisions

### AD-01: Technique Resolution at Simulation Prepare Time
Resolve CVE → technique mapping once during `CyberSimulationManager.prepare()`, not at exploit time.
Store resolved techniques in `simulation_config.json` as `entity_techniques: {cve_key: [T1190, T1059]}`.
At exploit time, attacker picks from the pre-resolved list. This avoids DB calls in the hot path.

**Trade-off:** Techniques are fixed at prepare time; if graph is enriched mid-simulation, new mappings
won't be reflected. Acceptable for the simulation window (≤ 30 days).

### AD-02: Probabilistic Model is Client-Side (Not LLM)
The exploit success probability model runs in `AttackSurfaceServer._action_exploit_cve()` as pure Python,
not via LLM. This ensures:
- Deterministic given a seed (reproducible simulations)
- No added latency per round
- Probability calculation is auditable (logged to decision trace)

**Trade-off:** LLM does not learn from the probability outcome. The LLM decides *what* to attempt;
the model decides *whether it succeeds*. This separation is correct.

### AD-03: Explainability via Extended JSONL + LLM Synthesis
Decision trace is written to `cyber_actions.jsonl` during the simulation (subprocess side).
LLM synthesis (narratives, counterfactuals, audit trail) happens in `report_agent.py` after
simulation completes (main process side). This keeps the subprocess simple and fast.

### AD-04: Counterfactuals Generated Once per Simulation
Counterfactuals are generated by the report agent at completion, not incrementally. They are
expensive (LLM call with full chain data as context). Cached in `simulation_runs.counterfactuals`.

### AD-05: Situation Room Explainability Fields are Optional
New fields (`threat_category_explanations`, `exposure_derivation`) are optional in the API response.
Existing consumers ignore them. Frontend renders them progressively if present.

### 2. Probabilistic Exploit Model (`attack_surface_server.py` — modified)

```python
@dataclass
class ExploitContext:
    cve_id: str
    is_kev: bool
    monitoring_active: bool
    detection_events: list[str]    # CVE IDs that have detection events
    controls_deployed: list[str]   # Control IDs deployed
    exploit_attempts: dict         # {cve_id: attempt_count}
    privilege_level: int

def _compute_exploit_probability(self, ctx: ExploitContext) -> tuple[float, list[str]]:
    """
    Returns (probability, modifier_reasons).
    modifier_reasons logged to decision trace.
    """
    base = 0.85 if ctx.is_kev else 0.60
    reasons = [f"base={base} ({'KEV' if ctx.is_kev else 'non-KEV'})"]
    modifiers = 0.0

    if ctx.monitoring_active:
        modifiers -= 0.15
        reasons.append("monitoring_active: -0.15")
    if ctx.cve_id in ctx.detection_events:
        modifiers -= 0.20
        reasons.append("detection_event_exists: -0.20")
    if ctx.controls_deployed:
        modifiers -= 0.30
        reasons.append(f"control_deployed ({len(ctx.controls_deployed)}): -0.30")
    if ctx.privilege_level == 0:
        modifiers -= 0.10
        reasons.append("no_foothold: -0.10")

    prior_attempts = ctx.exploit_attempts.get(ctx.cve_id, 0)
    if prior_attempts > 0:
        attempt_penalty = min(prior_attempts * 0.10, 0.30)
        modifiers -= attempt_penalty
        reasons.append(f"repeated_attempt×{prior_attempts}: -{attempt_penalty:.2f}")

    prob = max(0.05, min(0.95, base + modifiers))
    return prob, reasons
```

### 3. Action State Machine (`attack_surface_server.py` — modified)

```python
class AttackerPhase(str, Enum):
    RECON        = "recon"          # Must complete SCAN_SURFACE first
    EXPLOITATION = "exploitation"   # After first successful scan
    LATERAL      = "lateral"        # After first successful exploit
    ESCALATION   = "escalation"     # After first LATERAL_MOVE
    PIVOT        = "pivot"          # After ESCALATE_PRIVILEGES

def get_available_attacker_actions(self) -> list[str]:
    """Returns list of currently available actions based on attacker phase."""
    phase = self.attacker_phase
    if phase == AttackerPhase.RECON:
        return [SCAN_SURFACE]
    elif phase == AttackerPhase.EXPLOITATION:
        return [SCAN_SURFACE, EXPLOIT_CVE]
    elif phase == AttackerPhase.LATERAL:
        return [SCAN_SURFACE, EXPLOIT_CVE, LATERAL_MOVE]
    elif phase == AttackerPhase.ESCALATION:
        return [SCAN_SURFACE, EXPLOIT_CVE, LATERAL_MOVE, ESCALATE_PRIVILEGES]
    else:  # PIVOT
        return [SCAN_SURFACE, EXPLOIT_CVE, LATERAL_MOVE, ESCALATE_PRIVILEGES, PIVOT_TARGET]
```

## Data Flow

```
[Simulation Prepare]
  CyberSimulationManager.prepare()
    → TechniqueResolver.resolve_all(entities, db)
    → config.json["entity_techniques"] = {cve_key: [T-ids]}

[Per Round - Subprocess]
  attacker: LLM decides action + target
    → action_logger writes with decision_source, reasoning, game_state_snapshot
  attack_surface_server: compute_exploit_probability()
    → modifier stack computed, reasons logged
  attacker phase state machine: phase transitions logged

[Simulation Complete - Main Process]
  simulation_manager.complete()
    → parse cyber_actions.jsonl
    → batch upsert ALL entries (Attacker + Defender + Regulator) to agent_action_logs
    → report_agent.generate(full_chain_data, action_log)
        → board_narrative + tef + chain_narratives + counterfactuals + audit_trail
    → writeback_service.run_all(payload)
        → attack_chain_findings with explanation field
        → simulation_runs with counterfactuals + audit_trail
        → business_impact_findings (CFO/board)
        → threat_category_rollups with technique_ids (now diverse)

[Situation Room API]
  GET /v1/situation/ciso
    → compute_ciso() adds threat_category_explanations
  GET /v1/situation/board
    → compute_board() adds exposure_derivation
```
